# Database

- PostgreSQL 16. Schema source of truth: `database/prisma/schema.prisma`. Diagrams: [erd.md](erd.md).
- 97 tables and 312 foreign keys, all `ON DELETE RESTRICT` (posted records are never cascade-deleted).
- IDs are UUIDs; human document numbers (`number`) are separate, gap-free per scope (e.g. `S-DLA1-000123`, `PO-000045`, `JE-000981`).
- Scoped uniqueness: e.g. SKU and barcode per business, branch code per business, location code per branch, one open cashier session per register (partial unique index), one stock balance per (location, variant, batch) with `NULLS NOT DISTINCT`.
- Timestamps are `timestamptz` (UTC); display uses the business timezone.

## Migrations
| Migration | Content |
|---|---|
| `20261111090000_init` | Tables, enums, indexes, foreign keys — generated by `packages/db/tools/generate-ddl.ts` from the Prisma schema |
| `20261111090100_integrity_controls` | Hand-written CHECK constraints, deferred journal-balance triggers, period-lock trigger, immutability/append-only triggers, partial unique indexes |
| `20261111100000_session_refresh_grace` | Refresh-token grace window columns |

Commands: `pnpm db:migrate` (apply pending), `pnpm db:reset` (dev/test only), `pnpm db:check` (drift check), `pnpm db:generate` (client). The runner verifies checksums and refuses modified, already-applied migrations.

**Authoring new migrations:** change `schema.prisma`, then either run `prisma migrate diff --from-config-datasource --to-schema database/prisma/schema.prisma --script` on a machine where Prisma's schema engine is available, or write the SQL by hand in a new `database/migrations/<timestamp>_<name>/migration.sql`. Always finish with `pnpm db:check`.

## Notable structures beyond the requested list
`inventory_cost_pools` (the requested `inventory_cost_records` — current weighted-average state; history is in `stock_movements` with `pool_qty_after`/`pool_value_after`), `stock_adjustment_lines`, `funds_transfers`, `approval_policies`, `document_sequences`, `user_sessions`, `idempotency_records`, `notifications`, `tax_rates`, `bundle_components`. `return_inspections` are folded into `sales_return_lines` (condition, inspection notes, destination location).
